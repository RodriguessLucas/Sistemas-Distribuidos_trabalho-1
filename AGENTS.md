# Instruções do Trabalho 1 de Sistemas Distribuídos

Este projeto implementa aprendizagem federada com cliente e servidor Python via gRPC.

## Regra universal de preservação

Nenhuma regra original proveniente do código ou material fornecido pode ser
alterada, removida, enfraquecida ou contornada. Esta regra vale para todo o projeto,
incluindo implementação, testes, infraestrutura, documentação e skills.
Complete os TODOs preservando contratos, validações, ordem das operações,
arquitetura, parâmetros do modelo e comportamentos originais. Docker e ferramentas
devem se adaptar ao trabalho. Se houver conflito ou ambiguidade, registre o caso
e solicite esclarecimento antes de modificar a regra original.
A preferência por código sem comentários aplica-se ao código novo: a remoção de
dicas de TODOs concluídos não autoriza remover os requisitos que elas expressam.

Antes de implementar ou revisar o trabalho, leia as skills locais:

- `skills/sd-criterios-aceitacao/SKILL.md`: comportamento esperado e validação.
- `skills/sd-padrao-codigo/SKILL.md`: arquitetura, convenções e código sem comentários.

Consulte `ANALISE.md` para o diagnóstico inicial e a sequência de implementação.
O enunciado em `trabalho-1.pdf`, o guia em `codigo/start/README.md`, o contrato
`codigo/start/federated.proto` e os testes fornecidos são as fontes dos requisitos.
Distinga requisitos do material de sugestões de melhoria. Não altere testes para
acomodar erros da implementação.
